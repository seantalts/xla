# XLA Project - Claude Code Guide

## Building XLA Targets

### Prerequisites (Claude Code Remote Environment)

The remote environment has an egress proxy with JWT auth that requires special configuration for Bazel's JVM. The key issues and solutions:

1. **Bazelisk can't reach `releases.bazel.build`** — Set `BAZELISK_BASE_URL`:
   ```bash
   export BAZELISK_BASE_URL="https://github.com/bazelbuild/bazel/releases/download"
   ```

2. **Java SSL errors** — The proxy intercepts TLS. System CA store has the proxy certs but Bazel's embedded JDK doesn't. Use the system truststore via `--host_jvm_args` (do NOT modify Bazel's embedded JDK files — it triggers "corrupt installation" errors):
   ```
   --host_jvm_args="-Djavax.net.ssl.trustStore=/etc/ssl/certs/java/cacerts"
   --host_jvm_args="-Djavax.net.ssl.trustStorePassword=changeit"
   ```

3. **Java proxy auth (407)** — Java doesn't parse `HTTP_PROXY` URL format. Extract components and pass explicitly:
   ```
   --host_jvm_args="-Dhttp.proxyHost=<HOST>"
   --host_jvm_args="-Dhttp.proxyPort=<PORT>"
   --host_jvm_args="-Dhttps.proxyHost=<HOST>"
   --host_jvm_args="-Dhttps.proxyPort=<PORT>"
   --host_jvm_args="-Dhttp.proxyUser=<USER>"
   --host_jvm_args="-Dhttp.proxyPassword=<PASS>"
   --host_jvm_args="-Dhttps.proxyUser=<USER>"
   --host_jvm_args="-Dhttps.proxyPassword=<PASS>"
   --host_jvm_args="-Djdk.http.auth.tunneling.disabledSchemes="
   --host_jvm_args="-Djdk.http.auth.proxying.disabledSchemes="
   ```

4. **Go SDK download blocked** — `go.dev` and `dl.google.com` are not on the proxy allowlist. Go is pre-installed at `/usr/local/go`. The fix is to inline `grpc_extra_deps()` in `workspace0.bzl` and replace `go_register_toolchains(version = "1.22.5")` with `go_register_toolchains(version = "host")`. This avoids the Go SDK download entirely. You CANNOT simply pre-register go_sdk before grpc_extra_deps because grpc's `go_register_toolchains(version="1.22.5")` checks for existing rules and fails if go_sdk already exists with a version argument.
   Set `export GOROOT=/usr/local/go`.
   **This change is already applied in `workspace0.bzl` on the `claude/build-run-hlo-module-SlqzO` branch.**

### Install Bazelisk

```bash
curl -L https://github.com/bazelbuild/bazelisk/releases/latest/download/bazelisk-linux-amd64 \
  -o /usr/local/bin/bazel && chmod +x /usr/local/bin/bazel
```

Bazelisk auto-downloads Bazel 7.7.0 (per `.bazelversion`).

### Configure for CPU

```bash
python3 configure.py --backend=CPU
```

### Configure for GPU (CUDA)

```bash
python3 configure.py --backend=CUDA --cuda_compute_capabilities="9.0"
```

### Build run_hlo_module

Target: `//xla/tools:run_hlo_module` (defined in `xla/tools/BUILD` ~line 557, `xla_cc_binary`, `testonly = True`)

```bash
export BAZELISK_BASE_URL="https://github.com/bazelbuild/bazel/releases/download"
export GOROOT=/usr/local/go

# Extract proxy components from HTTP_PROXY env var
PROXY_HOST=$(echo "$HTTP_PROXY" | sed -E 's|http://[^@]+@([^:]+):.*|\1|')
PROXY_PORT=$(echo "$HTTP_PROXY" | sed -E 's|.*:([0-9]+)$|\1|')
PROXY_USER=$(echo "$HTTP_PROXY" | sed -E 's|http://([^:]+):.*|\1|')
PROXY_PASS=$(echo "$HTTP_PROXY" | sed -E 's|http://[^:]+:([^@]+)@.*|\1|')

bazel \
  --host_jvm_args="-Djavax.net.ssl.trustStore=/etc/ssl/certs/java/cacerts" \
  --host_jvm_args="-Djavax.net.ssl.trustStorePassword=changeit" \
  --host_jvm_args="-Dhttp.proxyHost=$PROXY_HOST" \
  --host_jvm_args="-Dhttp.proxyPort=$PROXY_PORT" \
  --host_jvm_args="-Dhttps.proxyHost=$PROXY_HOST" \
  --host_jvm_args="-Dhttps.proxyPort=$PROXY_PORT" \
  --host_jvm_args="-Djdk.http.auth.tunneling.disabledSchemes=" \
  --host_jvm_args="-Djdk.http.auth.proxying.disabledSchemes=" \
  --host_jvm_args="-Dhttp.proxyUser=$PROXY_USER" \
  --host_jvm_args="-Dhttp.proxyPassword=$PROXY_PASS" \
  --host_jvm_args="-Dhttps.proxyUser=$PROXY_USER" \
  --host_jvm_args="-Dhttps.proxyPassword=$PROXY_PASS" \
  build //xla/tools:run_hlo_module
```

### Run run_hlo_module

```bash
bazel-bin/xla/tools/run_hlo_module --platform=CPU --input_format=hlo xla/tools/data/add.hlo
```

### Other Useful Targets

- `//xla/tools:run_hlo_module_test` — Unit tests
- `//xla/tools:run_hlo_module_bin_test` — Binary integration tests
- `//xla/tools:hlo_module_loader` — HLO module loading library
- `//xla/...` — All XLA targets

### Key Configuration Files

- `.bazelversion` — Bazel version (7.7.0)
- `.bazelrc` — Main bazel config (imports tensorflow.bazelrc, warnings.bazelrc)
- `tensorflow.bazelrc` — Default build options, platform configs
- `xla_configure.bazelrc` — Generated by `configure.py`
- `configure.py` — Backend configuration (CPU/CUDA/SYCL)
- `xla/tools/BUILD` — BUILD file with run_hlo_module target

### Docker Build (Alternative)

Per `docs/developer_guide.md`, the recommended approach for full builds:
```bash
docker run -itd --name xla -w /xla -v $PWD:/xla \
  us-docker.pkg.dev/ml-oss-artifacts-published/ml-public-container/ml-build:latest bash
docker exec xla ./configure.py --backend=CPU
docker exec xla bazel build --spawn_strategy=sandboxed //xla/tools:run_hlo_module
```
